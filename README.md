# 微信跑步圈地小程序

在微信开发者工具中导入本目录并编译。未登录时，从任意入口打开小程序都会先进入登录页。勾选《隐私保护指引》，点「选择微信头像并登录」。选中头像后，`running` 云函数通过微信身份识别跑者、保存头像，并为首次登录的账号分配默认昵称，例如 `跑者_00001`。登录成功后回到原本要打开的页面，默认进入「个人中心」。取消选择头像会留在登录页。[微信头像选择说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile.html)

领地沿跑步轨迹的实际轮廓划分。遇到已有领地，只有两圈交叠的部分参与配速比较，两人各自在圈外的土地保持原有归属。示例中两圈交叠约 3,590 平方米。乙跑到 5:40/公里可以从甲手中夺下这片区域，跑到与甲相同的 6:00/公里则由甲守住。

## 微信开发者工具 · 云开发

服务端云函数名为 `running`，当前项目的环境为 `cloud1-d5gnvayfnb1fa1cd4`。在微信开发者工具打开本项目，点击 **云开发 → 云函数 → running** 可查看部署与日志。当前函数超时为 60 秒。发布新版本时，右键 `cloudfunctions/running`，选择「上传并部署：云端安装依赖」。

云函数通过微信调用上下文识别跑者；客户端传入的 `openid` 和 `player_id` 不参与身份判定。跑步、领地和资料存放在云数据库的 `running_state` 集合（权限设为「仅管理端可读写」），公开头像存放在云存储的 `running-avatars/`。头像需允许小程序读取，文件由云函数写入。初始公园原点沿用项目的 `31.23, 121.47`。需要指定其他公园时，在第一次开始跑步前设置函数环境变量 `PARK_LATITUDE` 和 `PARK_LONGITUDE`。

验证登录限制时，在「云函数 → 云端测试」以无微信用户身份调用 `{"action":"map"}`。返回的 `result.error` 包含 `code`、`status` 和 `message`，此时 `code` 为 `login_required`，`status` 为 `401`。验证已登录请求时，先在模拟器中登录，再在小程序调试器中运行 `wx.cloud.callFunction({ name: 'running', data: { action: 'me' } })`。返回的 `result` 包含当前跑者资料。

| action | 输入与结果 |
| --- | --- |
| `map` | 可选 `bounds` 对象，含数值型 `west/south/east/north`；返回当前范围内的领地和领主公开资料 |
| `leaderboard` | `period` 支持 `day`（默认）、`week`、`month`。按 `scope` 选择全国个人榜（`national`，默认）或省份榜（`province`），按 `metric` 选择本期净增面积（`area`，默认）或本期有效距离（`distance`）。返回所选 `period`、名次 `rank` 和成绩 `value`，单位分别为平方米和米。全国榜返回前 500 位跑者及 `rank_limit: 500`，省份榜返回所有有正成绩的省份。 |
| `login` | 首次或退出后传 `avatar_base64`，已登录时可省略；返回跑者编号、昵称、标识和头像云文件 ID |
| `me`、`updateAvatar`、`logout` | 分别查询本人资料和领地总面积、传 `avatar_base64` 换头像、退出并清除公开头像。`me.avatar_url` 是头像云文件 ID，`me.avatar_display_url` 是供个人中心显示的 10 分钟有效签名地址。 |
| `runStats` | 查询本人累计和周期统计。`period` 支持 `week`、`month`、`year`，`offset` 为 0 表示本期，负整数表示往期。返回累计和本期汇总、周期起止日期、各日或各月的里程分布。 |
| `runHistory` | 按结束时间倒序查询本期或指定 `bucket` 的跑步，每页 20 条。传统计返回的 `start` 固定周期，下一页使用 `next_cursor`。 |
| `achievements` | 查询本人的 7 项个人纪录和 4 类累计进度。纪录带成绩、完赛时间和来源跑步编号，累计进度带当前值与各档门槛。 |
| `updateNickname` | 传 `nickname` 修改本人昵称，支持 1 至 32 个字符，保存后返回完整个人资料 |
| `start` | `run_id`、`first_point`；用第一个有效定位点开跑 |
| `append` | `run_id`、`points`；按采集时间去重，可分批补传 |
| `finish` | 传 `run_id`、`ended_at` 和可选的 `points`。有效里程不足 300 米时返回 `recorded: false`、`run_id` 和 `player_id`。达到 300 米时返回结算明细和全程配速异常标记 `pace_anomaly`。重试返回首次结果。 |
| `getRun` | `run_id`；查询本人该次跑步、轨迹和结算结果。传 `include_points: false` 只读取结算明细。 |
| `lossReports` | 查本人失地战报，每页 20 条。第一页省略 `cursor`，下一页传上一页的 `next_cursor`，为 `null` 时读完。返回 `reports` 和微信提醒状态 `notification`。 |
| `lossReportBoundary` | 本人展开地块时传 `report_id` 和从 0 开始的 `region_index`。返回结算时该地块的 GCJ-02 GeoJSON Polygon，包含原始外环和内环。没有边界快照时 `geometry` 为 `null`，超出展示上限时另带 `reason: "too_complex"`。 |
| `subscribeLossNotice` | 用户在微信弹窗同意后，登记一次失地提醒。传服务端返回的 `template_id`、本次授权的 `grant_id` 和小程序 `env_version`。网络重试沿用同一个 `grant_id`。 |

## 个人中心与跑步手记

个人中心的「跑步手记」卡展示累计公里数、次数和用时，数据来自 `me.running_summary`。点「查看统计」可切换本周、本月和年度，或用箭头回看往期。点周柱图中的星期、月日历中的日期或年柱图中的月份可以筛选明细，再点某次跑步查看结算结果。

单次实跑的有效里程满 300 米即计入跑步记录、统计、成就和排行榜。达标的跑步按北京时间的完赛日期计入统计，周一为每周第一天。平均配速用累计用时除以累计公里数，单次最快配速取有里程记录中的最快单次平均配速。为 `running_state` 建立组合索引 `player_run_history`，字段顺序为 `value.player_id` 升序、`value.ended_at` 降序、`value.run_id` 降序。

## 我的成就

前往「个人中心 → 我的成就」可查看个人纪录和累计里程碑。本功能从启用后的实跑结算开始记录。同一场跑步重试只结算一次，在跑步明细里可以回看当次建立或刷新的纪录及解锁的档位。

跑步结算成功时，新建或刷新的个人纪录与新解锁的里程碑会合并在一个庆祝弹窗中。开发版或体验版可在「个人中心 → 成就弹窗测试」反复预览动画，测试数据仅在页面内展示。

个人纪录共 7 项：单次最远距离、最快 1 公里、最快 5 公里、单次新增领地最多、单次夺地最多、单周最高里程、历史最大领地面积。最快分段按整条有效轨迹计算，取跑完 1 公里或 5 公里的最短用时，计入分段途中的停留和定位空档。里程和分段纪录均支持未闭环的实跑。单周按北京时间周一至周日归集。新增领地含新占和夺得，夺地只算从其他跑者手中取得的面积。历史最大领地面积保留个人同时持有领地的最高值。

| 累计成就 | 解锁档位 | 计算方式 |
| --- | --- | --- |
| 跑步里程 | 10、50、100、500 公里 | 累加实跑有效里程 |
| 跑步天数 | 3、7、30、100 天 | 有有效里程的实跑按北京时间完赛日期去重 |
| 圈地面积 | 1 万、5 万、20 万、100 万平方米 | 累加新占和夺得的面积，失地保留以往进度 |
| 成功夺地次数 | 1、5、20、100 次 | 每场有夺地的实跑计一次 |

## 跑步测试

在开发版或体验版登录后，打开「个人中心 → 跑步测试」。回放无需定位，测试领地仅在本页内保留。「正常闭环」下连续点两次回放，可看到甲以 6:00/公里先占地，乙以 5:40/公里夺得约 3,590 平方米。点「重新测试」，先回放甲的路线，再将乙调为 6:00/公里并回放，即可验证同速由甲守住。

选「提前结束」可查看未闭环的原因，选「定位中断」可验证含定位空档的闭环仍能结算。要试自己的路线，在地图上依次点出拐点或拖动画线，再选「原地结束」或「跑回起点并结算」。

测试页在本地运行云函数的轨迹判定和领地结算代码。改动 `cloudfunctions/running/geometry.js` 后，运行 `node scripts/sync-demo-geometry.js` 同步到小程序包。

## 实地跑步

登录后点底部「实地跑步」查看附近领地。点地块或领主标记，地块会浮起，头像和昵称随顶面抬高，地图下方显示领主、面积和守地配速。点另一块地可以切换，点空地让地块落回。点「开始跑步」时小程序请求前后台定位授权，取得首个有效点才开始计时。跑完点结束，结算页按面积列出新占、夺得、守住或未夺得的区域。采点期间会在设备上缓存轨迹，暂时断网可在恢复连接后提交。

登录后，在「个人中心 → 管理资料 → 修改昵称」可以手动输入或使用微信键盘提供的昵称，再点「保存昵称」。初始昵称取自跑者编号。地图在其他跑者的地块上显示圆形头像和昵称。头像缺失或加载失败时只显示昵称。昵称最多显示四个字，超过时显示前三个字和省略号，点标记可看全名。退出登录会清除头像并返回登录页。同一微信账号再次登录时仍沿用原昵称、领地和跑步记录。

模拟器和真机使用同一个云开发环境。实跑需要在微信后台填写位置隐私用途，并为该 AppID 开通后台定位。[微信后台定位接口说明](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.startLocationUpdateBackground.html)

## 领地战报与微信提醒

打开「个人中心 → 领地战报」可查看谁在何时夺走了自己的地、丢失面积和当时的守地配速，点地块可查看位置。实跑结算有新占、夺得或守住的区域时，也能从结算页进入战报。同一场跑步从同一人手中夺走的区域合为一份战报，随领地易主提交，按最近的结算顺序展示。

点开新战报中的地块，地图按易主时的边界调整视野。战报列表只加载摘要，展开才读取该块轮廓，同一页面缓存最近查看的 20 块。单块边界超过 2,048 个坐标点或 64 KiB，以及仅存标注点的历史战报，都显示位置标记。在开发版可用「查看示例战报」查看普通地块、带孔地块和凹形地块。

提醒默认关闭。跑者在战报页点「订阅一次失地提醒」后，微信才会询问授权。同意后，下一次失地会通过微信「服务通知」提醒一次，点消息可进入战报页。跳过或拒绝都能正常跑步、圈地和查看战报。订阅用完后，可以再次主动订阅。[微信一次性订阅消息说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message-overview.html)

本项目微信账号已选用一次性模板「对战结果通知」。`running` 云函数内置对应模板 ID 和字段，消息打开订阅时使用的开发版、体验版或正式版。需要停用订阅入口时，将云函数环境变量 `LOSS_NOTICE_TEMPLATE_ID` 设为空字符串。

发布时，为 `running_state` 建立组合索引（`value.report.recipient` 升序、`value.loss_revision` 降序）和单字段索引（`value.notice_due_at` 升序）。部署 `running` 云函数后，在微信开发者工具对该函数执行「上传触发器」，确认 `dispatchLossNotices` 已启用，再发布带战报页的小程序。触发器每分钟处理已获授权的待发送提醒。[微信云开发定时触发器说明](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/guide/functions/triggers.html)

## 排行榜

点底部「排行榜」默认打开全国面积日榜。点「日榜」「周榜」「月榜」可切换周期，并保留当前的范围和指标。例如，选择「全国榜」「周榜」「距离榜」可查看本周个人里程排名，对应的云函数请求是 `{"action":"leaderboard","period":"week","metric":"distance"}`。

日榜从北京时间当天零点算起，周榜从周一零点算起，月榜从每月一日零点算起。每次跑步按结束时间归入三个周期，跨零点跑步和断网后补传也按这个规则计分。周期成绩从启用该功能后的首次完赛结算开始记录。

全国面积榜按跑者在本期净增加的领地面积排名。新占和夺地增加面积，失地扣减面积，守住自己的地块不重复得分。省份面积榜按省内本期新增的领地覆盖面积排名，同一块地在跑者间易主只改变个人成绩。距离榜分别按个人本期有效总里程和省内本期有效总里程排名。全国榜和省份榜都需要登录，有正成绩才上榜。

各榜先按精确成绩从高到低排序。成绩相同时，服务端先结算到当前成绩的跑者或省份排在前面。面积和里程分别计时。例如，失地后重新达到原面积，以重新达到时的结算时间为准。同一毫秒内达到相同成绩时，按跑者 ID 或省份代码升序确定名次。每个名次只有一位。

全国面积榜和距离榜各展示前 500 位跑者，下拉可刷新整份名单。请求带 `include_self: true` 时，云函数按微信调用身份返回 `self`。本人有正成绩且排在名单之外时，底栏显示「500 名以外」和本人成绩，接口返回 `self.rank: null` 和 `self.outside_limit: true`。该项成绩为零时显示「暂未上榜」。本人名次和名单随同一次刷新更新。

有效里程满 300 米的跑步按实际轨迹分配省内里程，无需围成领地。跨省地块按重合面积分到各省；地块易主时，相应全国个人成绩随之增减。同一片地在同省内易主，其覆盖面积只计一份。区划范围外的部分仅计入全国个人成绩。

`running_scores` 存放每位跑者的全国成绩和每个省级地区的集体成绩，集合权限设为「所有用户不可读写」，小程序通过云函数查询。每条周期成绩的 `board` 包含范围、周期和起始日期，例如 `national:week:2026-11-23` 和 `province:month:2026-11`。`subject` 为跑者或省份，`area_units` 以 0.01 平方米计，`distance_units` 以毫米计。`area_reached_at` 和 `distance_reached_at` 分别记录该项成绩最近一次变化的服务端时间，单位为毫秒。云函数在同一个数据库事务内提交完赛、领地、累计成绩及三个周期的成绩。为 `(board 升序, area_units 降序, area_reached_at 升序, subject 升序)` 和 `(board 升序, distance_units 降序, distance_reached_at 升序, subject 升序)` 建立组合索引。查榜使用成绩索引，全国榜另批量读取上榜跑者的公开资料。管理员可用服务端 `runs.scoreBaseline()` 从已结束跑步和当前地块重算累计成绩，用于对账。

服务端随云函数打包区划边界，按省加载，查询榜单无需外部地图服务。主要边界取自 2026 年 1 月 1 日的 CTAmap 快照。[CTAmap 数据和版本说明](https://www.shengshixian.com/pages/d35ae5/)

## 跑步数据

时间是设备采集或操作时刻的 Unix **秒**，可含小数。坐标统一用 GCJ-02，精度 `accuracy` 的单位是米。一个定位点示例如下。

```json
{"latitude":31.23,"longitude":121.47,"accuracy":8,"timestamp":1730000000}
```

同一采集时刻保留精度更好的点，精度相同时按经纬度稳定去重。点击结束前应把尚未确认送达的点一并放入 `finish`，以便服务端用完整轨迹一次结算。每次上传上限为 2 MiB。

## 判定及返回值

实跑按全程平均速度标记配速异常。服务端取运动期间精度误差不超过 50 米的定位点，按采集时间去重、排序，依次相连计算里程。总用时包含停留和定位空档。用原始里程除以总用时，超过 18 公里/小时（配速快于 3 分 20 秒/公里）时写入 `pace_anomaly: true`，等于或低于观察线时为 `false`。标记仅供查看，运动照常上报，统计、排行、成就与领地按各自规则结算。新记录的结算明细与跑步历史列表均返回此标记。配速展示值四舍五入到整秒。

实跑按整趟有效里程判定。满 300 米即保存记录并统计一次，途中围出的所有区域按全程平均配速结算，各块没有单独的里程或面积门槛。开放路线中途走完的小圈、沙漏形和多次交叉形成的各块都有效。同一区域重复绕行只计一次面积，沿原线折返的部分只计里程。起终点相距不超过 30 米时可补线形成边界，补线不计里程。没有围出面积的达标跑步照常保存。整趟不足 300 米只留重试回执，不计入历史、统计或领地。

结算返回 `distance_m`、`duration_s`、`pace_s_per_km`、`area_m2`、`valid_loop` 和圈地失败原因 `reasons`。首尾距离 `closure_distance_m` 和最长定位空档 `max_gap_s` 供查看轨迹。定位空档和局部速度突变均不单独否决整场，也不扣除相应路段的里程。

`outcomes` 中每一项是一个连通区域，包含 `geometry`、`area_m2`、`previous_owner`、`previous_pace_s_per_km`、`owner` 和 `pace_s_per_km`。

| outcome | 区域归属 |
| --- | --- |
| `claimed` | 新占空地，以本圈配速设防 |
| `captured` | 快于原领主，夺得交叠区域 |
| `defended` | 圈到自己的领地，交叠部分留下两次中更快的成绩 |
| `failed` | 同速或更慢，原领主守住交叠区域 |

两圈仅接触边线或顶点时，争夺面积为零。领地可被切成几块，也可以环绕着别人的领地。首次结算在同一数据库事务内完成，同速并发挑战由先占领者守住。

有效闭环结算时，服务端按轨迹的外接矩形查询可能相交或贴边的地块，再使用实际轮廓计算争夺。新占、切分或合并会局部更新空间索引，领主地块数和面积随同一次结算提交。各地块保留原始入账面积以及参与结算的顺序。

## 查询与配置公园地图

登录小程序后，可在开发者工具的小程序调试器中指定地图范围。

```js
wx.cloud.callFunction({
  name: 'running',
  data: { action: 'map', bounds: { west: 121.46, south: 31.22, east: 121.48, north: 31.24 } }
})
```

地图接口先用经纬度视野查询空间索引，再按候选地块的实际轮廓判断相交。省略范围时查询公园原点附近。索引和地块详情存放在 `running_state`，每次结算改变地块时，在同一事务内发布新地图和对应的索引根。

每个地块返回领主的 `owner`（玩家标识）、`owner_number`（编号）、`owner_display_name`（昵称）、`owner_avatar_url`（头像路径）、地块内部的标注点 `label_point`、守地配速、面积和完整轮廓。轮廓采用 GeoJSON Polygon 的坐标排列，每点为 `[经度, 纬度]`，坐标系为 GCJ-02。第一条环是外边界，后续各环是该领地内的空洞。含洞区域另附 `fill_rings`，供微信原生地图逐片填色。
